# Case 3 — Suricata Network Alert

## What happened?

A network security alert was generated by Suricata after suspicious traffic was observed between the Kali Linux test VM and the monitored Ubuntu endpoint.

This case demonstrates how network-based detection can be used in a SOC lab to identify suspicious activity such as scanning, reconnaissance, or attack traffic.

## Source

- Source host: Kali Linux test VM
- Source IP: 192.168.62.129
- Detection tool: Suricata
- Log source: `eve.json`
- Integrated monitoring: Wazuh
- Event type: Network IDS alert

## Target

- Target host: Ubuntu monitored host
- Target IP: 192.168.62.20
- Network role: Monitored endpoint
- Related traffic: Network connection attempts / suspicious packets

## Evidence

- Suricata generated a network IDS alert.
- The event was recorded in `eve.json`.
- The alert included source IP, destination IP, protocol, timestamp, signature, and severity information.
- Wazuh collected or displayed the related Suricata alert.

## Severity

Medium

Severity may be increased to High if the alert indicates confirmed exploitation, malware activity, command and control traffic, or successful compromise.

## Detection Logic

The activity was considered suspicious because Suricata detected network traffic matching an IDS rule.

### Detection condition:

If network traffic matches a Suricata IDS signature,
generate an alert and review the event context.

### Additional review condition:

If multiple alerts are generated from the same source IP against the same target,
the activity should be reviewed as possible reconnaissance or attack behavior.

## Investigation Steps

1. Reviewed the Suricata alert.
2. Identified the source IP address.
3. Identified the destination IP address.
4. Checked the destination port and protocol.
5. Reviewed the Suricata signature name.
6. Checked the alert category and severity.
7. Verified whether the traffic was expected in the lab scenario.
8. Reviewed related alerts from the same source IP.
9. Checked whether the target host showed signs of compromise.
10. Documented the result and recommended actions.

## Analysis

The Suricata alert indicates that suspicious network traffic was detected between the Kali Linux test VM and the Ubuntu monitored host.

In a SOC environment, this type of alert should be reviewed to determine whether the activity represents normal administrative traffic, scanning, reconnaissance, or an actual attack attempt.

Because the source host is Kali Linux, the traffic is especially relevant in a lab environment. Kali Linux is commonly used for security testing, scanning, and attack simulation. In this case, the activity was controlled and generated for testing purposes.

The alert confirms that Suricata was able to inspect network traffic and detect activity matching a known IDS rule.

## Risk

Suspicious network alerts may indicate:

port scanning;
service discovery;
vulnerability probing;
exploitation attempts;
unauthorized access attempts;
preparation for lateral movement.

The risk depends on the signature, protocol, destination port, and whether the target host shows additional suspicious activity.

## Recommended Actions

Review the Suricata alert details.
Identify the source and destination hosts.
Check whether the traffic was expected or authorized.
Review other alerts from the same source IP.
Check the target host for related authentication or system events.
Validate whether any service was successfully accessed.
Block or restrict suspicious source IPs if the traffic is unauthorized.
Tune Suricata rules if the event is a known false positive.
Continue monitoring the source IP for repeated activity.

## Recommended Preventive Measures
Keep Suricata rules updated.
Monitor high-risk ports and services.
Limit exposed services on monitored endpoints.
Use firewall rules to restrict unnecessary access.
Segment lab or production networks.
Correlate Suricata alerts with Wazuh endpoint logs.
Review network alerts regularly.

## Result

The lab successfully demonstrated detection and investigation of a Suricata network alert.

The event showed that Suricata can detect suspicious network traffic and provide useful details for SOC analysis, including source IP, destination IP, protocol, alert signature, and severity.

## SOC Analyst Conclusion

The observed Suricata alert should be reviewed as a suspicious network event.

In this lab, the traffic was controlled and generated for testing purposes. In a real environment, similar activity could indicate reconnaissance, service discovery, or an early stage of an attack.

The recommended action is to review the alert details, correlate the event with endpoint logs, and verify whether the target host experienced any related suspicious activity.
